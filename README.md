# Venera 日志收集（venera-logs）

这是 **Venera 中文源版** 的**诊断日志收集仓库**。App 里的「诊断与日志上传」源会把运行故障上报到这里，
按日期归档，供作者定位问题、做软件修补。

> **来源声明**：本仓库服务于 [venera-app/venera](https://github.com/venera-app/venera) 的**修改版**，
> 原项目非本仓库作者所写，本仓库只收集其修改版的运行日志。

## 目录结构

```
logs/YYYY-MM-DD/<设备ID>_<时间>.md      每次扫描生成一份报告
```

例如 `logs/2026-09-19/241e02a0b43c_2026-09-19_151603.md`。

## 报告里有什么

| 字段 | 说明 |
|---|---|
| 设备ID | 每台设备首次使用自动生成的随机 ID（可在源设置里「查看设备ID」） |
| 时间 / App版本 / 平台 / 语言 | 运行环境 |
| 源总数 | 本机安装的源数量 |
| 汇总 | 可用 / 失败 计数 |
| **逐源结果表** | 每个源在 **搜索 → 详情 → 章节 → 图片** 四步的成败，**失败时带原始报错文本** |
| 原始数据 | 完整 JSON（含尝试过的关键词、候选漫画、各步计数），便于精确复现 |

报告**不含**账号密码、Cookie、Token 等敏感信息（诊断源只做公开接口探测，不上传凭据）。

## 怎么上报（用户侧）

1. 在 App 的漫画源列表里添加 **【工具】诊断与日志上传**；
2. 展开该源的设置 → **设置 GitHub Token**（需要 `repo` 权限的 Personal Access Token）；
3. 点 **扫描全部源并上传诊断报告**，等它跑完即可。

Token 只保存在本机该源的私有数据里。不想给 Token 也可以用 **本地预览报告**，
生成后复制粘贴给作者。

## 怎么用来修补（作者侧）

```bash
# 列出今天的报告
gh api repos/token1008/venera-logs/contents/logs/$(date +%F) --jq '.[].name'

# 读某一份
gh api repos/token1008/venera-logs/contents/logs/<date>/<file>.md --jq '.content' \
  | base64 -d

# 或直接克隆
git clone https://github.com/token1008/venera-logs
```

看「逐源结果表」的**失败原因**列即可定位：是站点改版（选择器失效）、CDN 防盗链、
需要登录，还是网络不可达。原始数据段的 JSON 里有每一步的计数和尝试过的关键词。

## 说明

- 仓库是**公开**的，任何人都能读（方便作者在不同机器上取日志）。请勿上传含隐私的内容。
- 只收集**诊断报告**，不收集漫画内容、浏览记录或任何账号凭据。
